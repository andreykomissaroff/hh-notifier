# hh-notifier — персональный бот уведомлений о вакансиях hh.ru в Telegram

Self-hosted бот: раз в час проверяет новые вакансии hh.ru по **вашему профилю** (извлекается из вашего резюме с помощью ИИ) и присылает их в Telegram — ссылкой плюс полным очищенным описанием. Бесплатно 24/7 на Cloudflare Workers, ваш компьютер не участвует.

Никаких общих серверов: **вы деплоите бота на свой Cloudflare-аккаунт**, ваши данные (резюме, реакции, память поиска) лежат в вашем же хранилище и никому не передаются.

## Возможности

- **Персональный поиск**: профиль из вашего резюме (роль, технологии, домены) + сгенерированные поисковые запросы; наблюдение за выбранными ИТ-компаниями целиком.
- **Очищенные описания вакансий**: ссылка + структурированная карточка (компания, город, зарплата, навыки, полный текст).
- **Самообучение на реакциях**: кнопки 👍/👎 под каждой вакансией (три состояния — высокая/нейтральная/низкая); 👎 учит фильтр консервативно скрывать нерелевантное, сильное совпадение с профилем защищает целевые вакансии от скрытия.
- **Команды**: `/run` — прогон прямо сейчас; `/stats` — статистика обучения; ссылки в чат → описание; `/test`, `/help`, `/diag`.
- **Дайджест по расписанию**: ежечасно 07:00–21:00 МСК, только при наличии новых; предупреждения ⚠️ при сбоях.

## Известные ограничения (прочитайте до деплоя)

- **hh.ru закрыл анонимный API**: данные идут через веб-RSS (максимум 20 последних вакансий на запрос) и HTML-страницы вакансий. При изменениях на стороне hh.ru бот может сломаться — статус смотрите через `/diag` и логи.
- **Telegram в России**: доставка сообщений ботом идёт из Cloudflare и работает всегда; но **читать Telegram из РФ** может требовать VPN — это ограничение самой сети Telegram, не бота.
- Лимиты бесплатного тарифа Cloudflare с многократным запасом покрывают работу одного пользователя.

## Что понадобится (~15 минут)

1. Аккаунт Cloudflare ([dash.cloudflare.com](https://dash.cloudflare.com)) — бесплатный.
2. Бот в Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните **токен** (вида `123456:AAE...`).
3. Ваш chat_id: напишите своему боту `/start`, затем в браузере откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе найдите `"chat":{"id": ЧИСЛО}`. Это **chat_id**.

## Деплой через dashboard (без программирования)

1. **Создайте воркер**: Workers & Pages → Create → «Start with Hello World!» → имя `hh-notifier` → Deploy → **Edit code**.
2. **Вставьте код**: удалите шаблон, вставьте всё содержимое файла **`dist/worker.js`** из этого репозитория (один собранный файл) → Deploy.
3. **Создайте KV** (хранилище): Storage & Databases → KV → Create → имя `hh-notifier-state`.
4. **Привяжите KV**: воркер → Settings → Bindings → Add → тип **KV namespace**, имя переменной **`STATE`**, выберите `hh-notifier-state`.
5. **Подключите ИИ** (для онбординга): Settings → Bindings → Add → **Workers AI**, имя переменной **`AI`**.
6. **Переменные**: Settings → Variables and Secrets → Add:
   - `TELEGRAM_CHAT_ID` (Text) = ваш chat_id;
   - `TELEGRAM_BOT_TOKEN` (**Secret**) = токен бота;
   - `TELEGRAM_WEBHOOK_SECRET` (**Secret**) = любая случайная строка (придумайте).
7. **Cron**: Settings → Triggers → Cron Triggers → Add → `0 4-18 * * *` (это 07:00–21:00 МСК каждый час).
8. **Подключите webhook**: откройте в браузере `https://<имя-воркера>.<поддомен>.workers.dev/setup?key=<TELEGRAM_WEBHOOK_SECRET>` — ответ `Webhook was set`.
9. **Проверка**: `/test` боту в Telegram → придёт тестовое сообщение.

## Деплой через wrangler CLI (для уверенных)

```bash
git clone <этот репозиторий> && cd hh-notifier-cf-worker
npm install -g wrangler
wrangler login
wrangler kv namespace create STATE     # вставьте выданный id в wrangler.toml (kv_namespaces)
wrangler secret put TELEGRAM_BOT_TOKEN
wrangler secret put TELEGRAM_WEBHOOK_SECRET
# TELEGRAM_CHAT_ID впишите в wrangler.toml [vars]
wrangler deploy
wrangler kv key put "profile" --path my-profile.json --namespace-id=<ваш-id> --remote   # опционально
# подключить webhook: откройте https://<воркер>.workers.dev/setup?key=<секрет>
```

Важно: в `wrangler.toml` сейчас указан **id хранилища автора репозитория** — для CLI-деплоя замените на свой (шаг `kv namespace create`). Команды KV выполняйте с `--remote` (без флага новые версии wrangler пишут в локальный dev-хранилище, и воркер ключ не увидит).

## Онбординг: профиль из вашего резюме

1. `/start` в чате с ботом — если профиля ещё нет, бот объяснит и попросит резюме.
2. Пришлите текст резюме (можно файлом `.txt` с подписью `/resume`, или сообщением `/resume <текст>`). Достаточно разделов «Желаемая должность», «Опыт», «Навыки».
3. Бот через ИИ извлечёт роль, технологии, домены, покажет черновик и сгенерированные поисковые запросы.
4. `/confirm-profile` — сохранить. С этого часа дайджесты идут под ваш профиль.
5. Не понравилось извлечение — `/resume` ещё раз. Смотрите пример структуры в `profile.example.json`.

Настройки по желанию (правки в коде + Deploy): списки `companies` (ИТ-компании для наблюдения целиком), `excludeKeywords` (стоп-слова), `repliedIds` (уже откликнутые вакансии), пороги авто-скрытия в `CONFIG`.

## Команды бота

| Команда | Действие |
|---|---|
| `/run` | полный прогон прямо сейчас (с отчётом) |
| `/test` | проверка канала доставки |
| `/stats` | реакции, топ слов, авто-скрытия |

| `/diag?key=<секрет>` | диагностика (браузер): статус webhook, профиль, счётчики памяти |

## Как бот отбирает вакансии (конвейер прогона)

1. **Сбор из RSS**: для каждого поискового запроса и каждой компании-монитора берутся последние 20 вакансий hh.ru (сортировка по дате публикации). Отсекаются: уже показанные (дедуп по id, память 14 дней), старше 26 часов, содержащие стоп-слова (`excludeKeywords`), а для компаний — не-руководящие названия (`leadershipKeywords`). Все прошедшие помечаются «обработанными» и повторно не приходят.
2. **Обогащение**: для кандидатов скачивается полное описание (до 10 за прогон, пауза 1,2 с). Источник — `api.hh.ru`, при отказе (сейчас он отдаёт 403) — автоматически HTML-страница вакансии; после отказа API сутки ходят сразу по HTML, без двойных запросов.
3. **Скоринг** каждого кандидата по полному тексту: совпадения с профилем дают плюс (роль ×2, технологии ×1, домены ×0.5); веса слов из ваших 👍/👎 — название и навыки ×1.0, тело описания ×0.5 и только при весе |2|+.
4. **Авто-скрытие**: вакансия не показывается, если рейтинг ≤ **−4** и в нём участвует ≥3 «знакомых» слов. Вакансии, сильно совпадающие с профилем (есть роль или бонус ≥2.5), не скрываются никогда. Скрытые видны в `/stats` («Последние скрытые» с рейтингом).
5. **Доставка**: заголовок + по одному сообщению на вакансию (ссылка, карточка, описание; длинные режутся на части, кнопки — на последней части). Недоставленные вакансии автоматически возвращаются в очередь следующего прогона.

Ротации памяти: «обработано» — 14 дней, реакции и словарь слов — 45 дней, словарь весов ограничен 1200 словами. Повторно увиденная через месяц вакансия снова не придёт: фильтр свежести (26 ч) отсекает старое.

## Реакции 👍/👎

- У каждой вакансии **три состояния**: 👍 высокая, 👎 низкая, без реакции — нейтральная.
- **Другая кнопка заменяет** реакцию (👍 → 👎), **повтор той же — снимает** (возврат в нейтральную).
- Текущее состояние видно **галочкой ✅** на кнопке; подтверждение дублируется всплывашкой.
- Порядок кнопок: 👎 слева, 👍 справа.
- У длинной вакансии (несколько сообщений) кнопки — **только на последнем сообщении**.
- Веса слов сдвигаются на разницу состояний (👍 → 👎 = −2 по словам вакансии); пиксельный вклад тела описания — только от подкреплённых весов (см. конвейер, п. 3).

## Надёжность доставки

- Ретраи при 429/5xx от Telegram (до 3 попыток, с уважением к `retry_after`); 4xx не повторяются.
- Вакансии, чьи сообщения не доставились, **возвращаются в очередь** следующего прогона — потеря «молча» невозможна. В `/run` это видно: «⚠️ доставлено M из N».
- Алерты ⚠️ при сбоях RSS и при серийных сбоях скачивания описаний (только на переходе «работало → сломалось»).
- Ретроспективные логи (3 дня): dashboard → Worker → Logs → **Past logs** — там же точные причины отказов Telegram.

## Ключевые параметры (src/config.js)

| Параметр | Значение | Смысл |
|---|---|---|
| `negativeScoreToSkip` | −4 | порог авто-скрытия по негативному рейтингу |
| `minWeightedWords` | 3 | минимум «знакомых» слов для текстового скоринга |
| `titleMinWeightedWords` | 2 | то же для скоринга по названию (текст недоступен) |
| `wordWeightCap` | ±5 | предел веса одного слова |
| `maxEnrichPerRun` | 10 | потолок скачиваний описаний за прогон |
| `enrichPauseMs` | 1200 | пауза между скачиваниями |
| `maxAgeHours` | 26 | свежесть вакансий |
| cron | `0 4-18 * * *` | расписание (07:00–21:00 МСК, ежечасно) |

## Как устроен код (для правок)

```
src/
  index.js    — точка входа: cron + HTTP-роутер + webhook-команды
  config.js   — НАСТРОЙКИ ИНСТАНСА: запросы, компании, стоп-слова, пороги, профиль-пример
  state.js    — KV: состояние, профиль, ротации
  feed.js     — RSS hh.ru: задачи, парсинг
  enrich.js   — описания вакансий (api.hh.ru → HTML-фолбэк, кэш отказа)
  scoring.js  — скоринг: профиль + реакции + авто-фильтр
  learn.js    — кнопки 👍/👎 и /stats
  profile.js  — модель профиля, генерация поисковых запросов
  onboard.js  — ИИ-извлечение профиля из резюме
  telegram.js — отправка, кнопки, шаблоны сообщений
  notifier.js — конвейер прогона
```

Правки в `src/` → `wrangler deploy`. Для dashboard-пути пересоберите единый файл:
`npx esbuild src/index.js --bundle --format=esm --outfile=dist/worker.js` и вставьте его в редакторе воркера.

## Диагностика проблем

- Бот молчит на кнопки/команды → откройте `/diag?key=<секрет>`: показывает статус webhook (`allowed_updates` должны содержать `message` и `callback_query`), сохранённый профиль (title, число ролей, число запросов) и счётчики памяти (seen/weights/feedback). Если `profile: null`, а ключ заливался — запись могла уйти в локальный dev-KV: повторите `kv key put` с `--remote`.
- Если `allowed_updates` неполные — повторно откройте `/setup?key=…` **актуальной** версии воркера (кэшированная старая версия перерегистрирует webhook со старым списком).
- Ошибки загрузки hh.ru (403) → hh ограничивает адреса Cloudflare; подождите или переезжайте на российскую площадку (Yandex Cloud Functions + CF-прокси к Telegram).
- Логи прогона: dashboard → Worker → Logs (живой поток или Past logs за 3 дня), затем `/run`. В логе ищите строки `sendMessage failed` и `⚠️ Не доставлено`.

## Лицензия и данные

Код открыт. Резюме, реакции и история поиска хранятся в KV вашего Cloudflare-аккаунта. Токен бота храните только в Secrets (никогда не коммитьте). Пример профиля владельца (`my-profile.json`) можно удалить или заменить своим.
